# Railway Deployment Guide

This guide walks you through deploying the AI Job Application Assistant to Railway.

## Prerequisites

1. A Railway account (sign up at https://railway.app)
2. Railway CLI installed (optional): `npm install -g @railway/cli`
3. Claude API key from https://console.anthropic.com/

## Deployment Steps

### 1. Create a New Railway Project

1. Go to https://railway.app/new
2. Click "New Project"
3. Choose "Deploy from GitHub repo" or "Empty Project"

### 2. Add PostgreSQL Database

1. In your Railway project, click "New"
2. Select "Database" → "PostgreSQL"
3. Railway will automatically provision a PostgreSQL database
4. Note the connection details from the "Variables" tab

### 3. Deploy Backend (Spring Boot)

#### Option A: From GitHub (Recommended)

1. Click "New" → "GitHub Repo"
2. Select your repository
3. Set the root directory to `/backend`
4. Railway will auto-detect the Maven project

#### Option B: From Railway CLI

```bash
cd backend
railway login
railway init
railway up
```

#### Set Environment Variables

In the Railway dashboard, go to your backend service → Variables:

```
DATABASE_URL=jdbc:postgresql://${{Postgres.PGHOST}}:${{Postgres.PGPORT}}/${{Postgres.PGDATABASE}}
DB_USERNAME=${{Postgres.PGUSER}}
DB_PASSWORD=${{Postgres.PGPASSWORD}}
CLAUDE_API_KEY=your-claude-api-key
FRONTEND_URL=https://your-frontend-url.railway.app
```

Railway automatically provides Postgres variables you can reference with `${{Postgres.VAR_NAME}}`.

#### Configure Build Settings

Railway will auto-detect Maven, but you can customize:

- Build Command: `mvn clean package -DskipTests`
- Start Command: `java -jar target/*.jar`

### 4. Deploy Frontend (React)

#### Create Frontend Service

1. Click "New" → "GitHub Repo" (or empty service)
2. Set root directory to `/frontend`
3. Railway will auto-detect Node.js/Vite

#### Set Environment Variables

```
VITE_API_URL=https://your-backend-url.railway.app/api
```

**Important:** Get your backend URL from the backend service settings.

#### Configure Build Settings

- Build Command: `npm install && npm run build`
- Start Command: `npx serve -s dist -p $PORT`

Or use the provided Dockerfile for Nginx serving.

### 5. Initialize Database

Railway doesn't automatically run SQL scripts, so you need to initialize the database:

#### Option A: Using Railway CLI

```bash
railway login
railway link  # Select your project
railway connect postgres  # Opens psql
```

Then run:
```sql
\i database/schema.sql
\i database/data.sql
```

#### Option B: Using a Database Client

1. Get connection string from Railway dashboard
2. Connect using pgAdmin, DBeaver, or psql
3. Execute `schema.sql` and `data.sql`

### 6. Configure Custom Domains (Optional)

1. Go to service Settings → Networking
2. Click "Generate Domain" for a Railway subdomain
3. Or add your custom domain

### 7. Update CORS Configuration

Once you have your frontend URL:

1. Update backend `FRONTEND_URL` environment variable
2. Redeploy backend service

### 8. Test the Deployment

1. Visit your frontend URL
2. Upload a test resume
3. Paste a job description
4. Click "Enhance Resume"
5. Verify the enhanced resume downloads successfully

## Environment Variables Summary

### Backend Service

| Variable | Description | Example |
|----------|-------------|---------|
| `DATABASE_URL` | PostgreSQL JDBC URL | `jdbc:postgresql://host:5432/db` |
| `DB_USERNAME` | Database username | `postgres` |
| `DB_PASSWORD` | Database password | Generated by Railway |
| `CLAUDE_API_KEY` | Anthropic API key | `sk-ant-api03-...` |
| `FRONTEND_URL` | Frontend URL for CORS | `https://your-app.railway.app` |

### Frontend Service

| Variable | Description | Example |
|----------|-------------|---------|
| `VITE_API_URL` | Backend API URL | `https://backend.railway.app/api` |

## Monitoring and Logs

- View logs in Railway dashboard under each service
- Check Spring Boot Actuator health: `https://backend-url/api/health`
- Monitor PostgreSQL usage in database service metrics

## Troubleshooting

### Backend fails to start

- Check logs for database connection errors
- Verify `DATABASE_URL` format is correct (JDBC format)
- Ensure Claude API key is valid

### Frontend can't reach backend

- Verify `VITE_API_URL` is set correctly
- Check CORS: backend `FRONTEND_URL` must match frontend domain
- Ensure backend health endpoint returns 200: `/api/health`

### Database connection issues

- Verify PostgreSQL service is running
- Check connection variables are correctly referenced
- Ensure database is initialized with schema and data

### Claude API errors

- Verify API key is valid
- Check Anthropic API status
- Review API usage limits

## Cost Estimate

Railway pricing (as of 2024):

- **Hobby Plan**: $5/month
  - Includes $5 usage credit
  - Suitable for personal projects and demos
  
- **Pro Plan**: $20/month
  - Includes $20 usage credit
  - Better for production apps

Each service consumes resources:
- PostgreSQL: ~$1-2/month
- Backend (Spring Boot): ~$3-5/month
- Frontend (Node/Nginx): ~$1-2/month

**Total estimated cost**: ~$5-9/month on Hobby plan

**Claude API costs** are separate:
- Check current pricing at https://anthropic.com/pricing
- Typical cost per resume enhancement: $0.01-0.05

## Scaling

Railway auto-scales based on traffic:

- **Vertical scaling**: Increase memory/CPU in service settings
- **Horizontal scaling**: Add replicas (Pro plan required)

For high traffic:
- Enable connection pooling (HikariCP is already configured)
- Add Redis caching for job keywords
- Consider CDN for frontend assets

## Backup and Maintenance

### Database Backups

Railway provides automatic daily backups on Pro plan. For manual backups:

```bash
railway connect postgres
pg_dump -h host -U user -d database > backup.sql
```

### Updates and Redeployment

1. Push changes to GitHub
2. Railway auto-deploys on push (if GitHub integration enabled)
3. Or manually trigger: `railway up` from CLI

## Security Checklist

- [ ] Claude API key is set as environment variable (not hardcoded)
- [ ] Database credentials are Railway-managed
- [ ] CORS is configured with specific frontend URL (not `*`)
- [ ] HTTPS is enabled (Railway provides by default)
- [ ] No sensitive data in version control (.env in .gitignore)
